# 研究 01 数据源映射规范

## 目的

将医院原始系统中的字段，透明映射到研究 01 的标准表。映射工作应在受控数据环境中完成；公开仓库只保存空白模板和规则，不保存源字段样例、患者记录或内部系统截图。

## 数据源类别

| 源系统 | 典型内容 | 映射目标 |
| --- | --- | --- |
| 电子病历 / 病案首页 | 人口学、诊断、手术日期、症状、共病、出院信息 | `patient_baseline`、`index_surgery_pathology` |
| LIS / 内分泌检验 | IGF-1、GH、OGTT、参考区间、检测平台、采样时间 | `preop_endocrine`、`early_postop`、`followup_events` |
| PACS / RIS | MRI 日期、协议、影像报告、Knosp、体积和结构受累 | `preop_mri`、`early_postop`、`followup_events` |
| 手术麻醉 / 手术记录 | 入路、术中海绵窦受累、切除程度、残留原因、并发症 | `index_surgery_pathology`、`reoperation_events` |
| 病理系统 | 转录因子、激素 IHC、Ki-67、核分裂、p53、复核 | `index_surgery_pathology` |
| 放疗计划系统 | GK/SRS 技术、日期、靶区、剂量、分割、视路剂量 | `radiotherapy_events` |
| 药房 / 用药医嘱 | 药物、剂量、频率、开始停止、调整原因 | `medication_events` |
| 随访 / 研究数据库 | 进展裁决、再治疗、视功能、垂体功能、生活质量、失访 | `followup_events` |

## 映射必须回答的六个问题

对每一个目标变量，映射表必须记录：

1. 源系统与源字段名称；
2. 源数据类型、单位和允许值；
3. 提取逻辑与时间窗口；
4. 标准化/转换规则；
5. 质控规则与人工复核条件；
6. 缺失、冲突和无法映射时的处理。

## 优先映射顺序

### 第一优先级：没有这些就不能开始

- 去标识化 `patient_id` 与首次手术日期；
- 术前 MRI 与 Knosp/海绵窦侵袭；
- 首次术后 MRI 与残留状态；
- 早期 IGF-1/GH、检测日期、单位与参考区间；
- 药物、SRS/GK、再手术的实际发生日期；
- 影像进展/再治疗与最后无事件随访日期。

### 第二优先级：提升可解释性与调整能力

- 术后残留体积与位置；
- 视觉、垂体轴功能、术中残留原因；
- 病理谱系、颗粒化模式、Ki-67、核分裂和 p53；
- 放疗靶区、剂量、视觉通路剂量；
- 药物剂量调整、依从性与不耐受。

### 第三优先级：机制与扩展分析

- 影像组学及其分割/软件版本；
- 胚系/体细胞遗传、转录组、蛋白组、代谢组；
- 患者报告结局与长期功能评估。

## 冲突解决规则

- **日期冲突：** 保留各来源日期与来源优先级；不静默覆盖。
- **单位冲突：** 先保留原始数值/单位，再用版本化函数派生标准值。
- **影像结论冲突：** 原报告与中央复核并存；主分析预先指定采用哪一种。
- **手术残留冲突：** 分开保存术者判断与首次术后 MRI；不得强行合成。
- **治疗日期冲突：** 以实际给药、实际照射或实际手术日期为主要暴露时间；计划/开单日期另存。

## 映射审核流程

```text
字段清单 → 抽样核对 → 映射规则草案 → 双人复核 → 冻结版本
     ↑                                              ↓
     └──────── 发现缺失、冲突或定义变化时修订 ────────┘
```

## 版本要求

- 每次提取都要有映射表版本、提取日期、代码版本和数据时间截点。
- 原始字段不删除；标准化字段与派生字段分层保存。
- 变量定义变化必须更新数据字典、映射表和分析日志。

## 下一步

在安全环境中，用 `data_mapping_template.csv` 对每一张研究表完成字段级映射；映射完成后，再运行数据可用性报告并进入准备度闸门审核。
